# ADR-0046: Schema-driven управление конфигурацией в web UI

## Статус

Принято.

## Дата

2026-08-03

## Контекст

Идея: оператор в проде должен смотреть, менять, применять конфигурацию бота
через web UI, импортировать/экспортировать файл конфигурации; новые плагины
с новыми настройками должны появляться в UI без правки фронтенда
(`docs/ideas/config-file-and-schema-driven-settings.md`).

Текущее состояние:

- Страница «Настройки» — заглушка: `src/queue-monitor/ui/src/pages/SettingsPage.jsx:4`
  («Раздел в разработке», список пунктов);
- Плагины экспортируют только `routes` (`src/bot-platform/core/plugin-loader.js:54`),
  декларации настроек нет;
- Секреты не должны раскрываться через API/UI/логи (ADR-0013, ADR-0029);
- Dashboard уже имеет auth (Bearer + session, ADR-0034/ADR-0035) и
  HTTP-сервер, на который можно добавить маршруты.

### Проблема

- Без декларации схемы невозможно отрендерить формы настроек и провалидировать
  ввод — пришлось бы хардкодить форму под каждую настройку и каждый плагин;
- Каждый новый плагин с настройками требовал бы изменения фронтенда;
- Импорт/экспорт JSON требует описания структуры (схемы) для валидации и
  редакции секретов.

### Требования

1. UI рендерит формы настроек динамически, без hand-written форм на каждый
   параметр;
2. Новый плагин с настройками появляется в UI автоматически;
3. Секреты маскируются, редактируются через отдельный flow с подтверждением
   и аудитом (ADR-0029);
4. Импорт/экспорт JSON: экспорт редактированный, импорт → валидация →
   staged → diff-превью;
5. Схема системы (секции `bot`/`queue`/`ingress`/`monitor`) и плагинов —
   единый формат (тип, default, required, secret, enum, min/max);
6. Ноль новых внешних зависимостей в bot-platform (ADR-0015).

## Решение

Ввести **schema-driven конфигурацию** поверх file-first ядра (ADR-0045).

### Схемы

- Единый формат схемы поля: `{ type, default, required, secret, enum, min,
  max, description, section }`. Типы: `string`, `number`, `boolean`, `enum`,
  `list`, `secret` (строка, маскируемая).
- Системная схема описывает секции `bot`, `queue`, `ingress`, `monitor` —
  она же используется для валидации `zyablik.config.json` (ADR-0045).
- Плагин объявляет `configSchema` рядом с `routes`
  (`src/bot-platform/plugins/identity/index.js` — первый кандидат).
  `plugin-loader.js` валидирует схему при загрузке (по аналогии с
  `validatePlugin`, строка 39).

### Web UI (страница «Настройки»)

- `SettingsPage.jsx` из заглушки превращается в рабочий экран:
  просмотр effective-конфига, редактирование в staged-состоянии,
  diff перед Apply, кнопки Apply / Rollback / Export / Import;
- Формы рендерятся из merged-схемы (`GET /api/config/schema`): секции
  системы + плагины; новый плагин появляется автоматически.

### API (dashboard-сервер, существующий auth)

| Маршрут | Назначение |
|---|---|
| `GET /api/config` | effective-конфиг (секреты редактированы) |
| `GET /api/config/schema` | merged схема для динамических форм |
| `PUT /api/config/stage` | сохранить изменения в staged |
| `GET /api/config/stage` | текущий staged + diff |
| `POST /api/config/apply` | записать файл + рестарт (ADR-0045) |
| `POST /api/config/rollback` | восстановить last-known-good |
| `GET /api/config/export` | скачать редактированный JSON |
| `POST /api/config/import` | загрузить JSON → валидация → staged + diff |
| `POST /api/config/secret/reveal` | разовое раскрытие секрета (подтверждение + аудит) |

- Auth: Bearer-ключ и session (ADR-0035) — те же, что у существующих
  `/api/metrics/*` и `/api/archive/*`.
- Секреты никогда не возвращаются в списках/ответах: только маска и факт
  «задан / не задан»; reveal — отдельный аудируемый вызов.
- Экспорт по умолчанию редактирует секреты до `$VAR`-ссылок (ADR-0045).

## Почему schema-driven

- Одна декларация используется трижды: валидация файла (ADR-0045), рендер
  форм и редакция секретов — нет трёх рассинхронизированных описаний;
- Плагины описывают свои настройки сами — появление нового плагина не
  требует правки `SettingsPage.jsx` и API;
- Управляется без новых внешних зависимостей (простые типы + stdlib).

## Рассмотренные альтернативы

### Hand-written формы под каждую секцию и плагин

Точный контроль UX.

Минус: каждая новая настройка и каждый новый плагин требуют правки
React-кода; дублирование валидации фронт/бэк. Отклонено — противоречит
требованию «новые плагины без правки фронтенда».

### Только редактирование файла без UI

UI показывает только просмотр, изменения — через импорт файла.

Минус: оператор не получает «изменение через UI», а только
импорт/экспорт; по требованию идеи нужны обе возможности. Отклонено для
MVP; «только просмотр» — допустимый future mode.

### Секреты в открытом виде в UI (упрощение)

Меньше кода.

Минус: утечки через логи/скриншоты, нарушение ADR-0013/ADR-0029. Отклонено.

### Сторонний форм-движок (react-jsonschema-form и т.п.)

Готовая библиотека.

Минус: новая внешняя зависимость в уже существующем React-проекте (там
зависимости допустимы), но для простых типов схемы избыточно; контроль
дизайн-системы (ADR-0036) сохраняется при собственной генерации форм.
Допустимо как future, для MVP — собственные простые рендеры на компонентах
дизайн-системы.

## Последствия

- `SettingsPage.jsx` становится рабочей страницей (React Router уже есть —
  ADR-0042);
- Новые маршруты `/api/config/*` на dashboard-сервере под существующим auth;
- `plugin-loader.js` валидирует `configSchema`; плагин `identity` получает
  первую схему как образец;
- Схемы системы — источник валидации файла (ADR-0045), одна декларация;
- Аудит операций apply/import/rollback/reveal (ADR-0029);
- Документация: idea → ADR, INSTALL.md, `docs/zabbix-media-type.md` при
  необходимости, README/CHANGELOG.

## Тесты

- `npm test` + новые unit-тесты: валидация схем плагинов при загрузке,
  merged-схема, редакция секретов в ответах/экспорте, diff staged,
  rollback;
- UI: Storybook для новых компонентов страницы «Настройки» (ADR-0036),
  существующие тесты `src/queue-monitor/ui`;
- policy-тесты: секреты не появляются в API-ответах/экспорте
  (расширение `docs-leak-guard.test.js` при необходимости);
- No новых внешних зависимостей в bot-platform (ADR-0015).
